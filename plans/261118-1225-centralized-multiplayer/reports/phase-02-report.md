# Phase 2 match worker handoff

The managed Godot worker owns admission and gameplay for one room generation. It binds one of UDP 7778–7780, reports readiness only after authenticating to the directory’s loopback TCP listener, and keeps playing when control is lost. The [worker control schema](../../../multiplayer/worker-control.schema.json) defines launch configuration, framing, signing, recovery, ticket delivery, and the client RPC contract for Phases 3 and 4.

The worker reserves the creator first and keeps a five-seat ledger. ENet admission binds a one-time ticket proof to the room, generation, peer, and fresh nonces. The server validates movement, targets the existing 20 Hz snapshot stream only to admitted players, and owns Ready, start, role, mode, leadership, and disconnect decisions. Active clients use their existing input stream for liveness. After 900 ms without input, the worker temporarily pauses the match (timers, enemies, projectiles, channels and actions frozen). A departure is final only once ENet confirms the loss through its own disconnect/timeout; if the player's traffic returns first, the match resumes with their seat and no vote is held. ENet runs a 200 ms ping interval with a retransmission factor of 8 and 1,500/3,000 ms minimum/maximum timeout thresholds, so a confirmed departure lands well inside the client's 5-second liveness deadline (its watchdog is 4,800 ms to leave polling time). The Bot outcome converts each vacancy in place. The No bot outcome removes each vacancy and drops its inventory.

## Control protocol notes

The worker emits a signed heartbeat every 1,000 ms and on report changes. Each heartbeat carries `maxFrameMs`, the longest interval between worker control updates since the previous heartbeat; the manager's heartbeat and socket deadline is 2,800 ms against that 1,000 ms interval. Manager commands are `reserve` (signed, carrying `expiresAt` between the directory and worker), `cancel {requestId}` (the directory cancels by request ID, and an optional `requestId` echoes on the cancellation acknowledgement), `ping`, and `close`. A successful `reserve` reply carries `{requestId, code, ticketId, secret, expiresAt, ttlMs}`, where `ttlMs` is the bounded remaining lifetime on the worker's monotonic clock. On Start, the worker sends `reservation_cancelled {requestId, reason: "room_started"}` for each outstanding reservation, and an ENet proof for one of those invalidated tickets receives the terminal `room_started` result rather than a generic refusal.

## Local verification

- `tests/match-worker-check.gd` passed. It covers creator-first admission, five-seat capacity, replay and expiry, authorization, movement limits, vote deadlines and ties, frozen state, replacement behavior and population scaling, post-result cleanup, and the continuous-empty timer.
- `tests/match-worker-integration.py` passed against Godot 4.7.2 on macOS arm64. The suite checks independent processes on the fixed ports, signed TCP registration and heartbeat behavior, real ENet admission and snapshot isolation, movement validation, snapshot cadence, recovery across manager process death, stale generation rejection, leader succession, timeout and resume, authenticated shutdown, port reuse, and a real 60-second empty exit. The scripted fixture uses the control protocol directly. One preliminary run missed the snapshot receive-rate assertion. Later runs, including the final run, passed it.
- The same ENet suite also counted raw snapshot arrivals before the client's admitted guard (zero to an unadmitted peer) and asserted the unauthenticated RPCs left the authoritative room state unchanged. It measured the upstream-loss pause at 895 ms, departure confirmation at 2,801 ms after sustained upstream loss, and a shorter recoverable burst that resumed without a vote. It also checked expired-peer removal from SceneMultiplayer and heartbeat `maxFrameMs` reporting through a controlled 700 ms worker stall. An outstanding reservation pauses the 60-second empty timer, and Gather/Revive/Enter progress survives the pause until fresh input arrives after resume; a replacement bot reselects a node when its carried resource fills.

## Still unverified

- Phase 1’s macOS and Windows exports, a clean Linux worker export, hosted WSS and certificate trust, exported map packaging, and cross-network gameplay remain open. Phase 2 adds no evidence for the actual Colyseus manager, service supervision on Linux, or hosted three-room capacity under load.
- The graphical hosted Ready and timeout screens are owned by Phase 4. The server rules and snapshot fields were exercised by headless clients here.
