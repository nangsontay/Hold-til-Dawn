# Centralized multiplayer migration review

**Verdict: Not ship-ready.** The local stack passed the requested suites and a three-room recovery smoke. Release activation can report success with unusable worker supervision, valid tickets depend on the player's system clock, and the pre-admission snapshot test can pass even if a snapshot arrives. Public, exported, and target-host gates remain open.

## High

1. **Release activation can succeed with no launchable workers.** Missing or unreadable systemd worker units are treated as busy. The manager finishes reconciliation after two seconds regardless of whether the supervisor resolved those slots. With no registered rooms, the directory can report **Server full**, /health returns 200, and drained activation succeeds. The operator can reopen admissions on a release that cannot create any room. Distinguish supervisor errors from live ownership, expose degraded readiness, and require an authenticated worker launch and exit in the release rehearsal. ## Medium

2. **A valid ticket can expire on a player's clock before the worker sees it.** The client subtracts its wall clock from the server's absolute expiry. A clock more than one ticket lifetime ahead rejects a newly issued seat and leaves it reserved. Use the monotonic connection deadline and let the worker enforce expiry, or send a bounded duration for the client to use. Test a skewed client clock. [main.gd:309](../../main.gd#L309) · [match-worker.gd:198](../../match-worker.gd#L198) · [match-worker.gd:218](../../match-worker.gd#L218)
3. **The pre-admission snapshot test counts only snapshots the client accepts.** The silent fixture leaves my_id zero. Other negative-admission clients stay in CONNECTING. Both paths return from s_snap() before the fixture's counter, so a premature snapshot would still give a passing zero. Source inspection confirms the worker currently targets admitted peers. Count raw snapshot arrivals before the client's guard and assert the unauthenticated RPCs leave authoritative state unchanged. The Phase 2 and Phase 5 reports overstate the network test's leakage coverage. 4. **Cancel leaves the seat reserved on the worker.** A player who cancels a Join cannot immediately retry the same room from that lobby session while the ticket holds the identity. A cancelled Create can also occupy one of the three ports until expiry. The hosted suite confirms this behavior and Phase 4's report records it, but the checked Phase 4 requirement includes clearing reservations on cancellation. Propagate explicit cancellations by request ID and cancel late reservations on the original worker generation. Keep the worker TTL for lost lobby connections. 8. **Release version checks can approve mixed artifacts.** The directory has no application-level compatibility check before Create or Join. The worker compares a manually maintained client build string, so mismatched maps or snapshot contracts can pass if a release forgets to bump it. Validate the supplied Godot template against the pinned build, derive or check compatibility identifiers during packaging, and exercise both compatible and incompatible peers before reopening after rollback. ## Low

9. **The client test's forced cleanup misses detached workers.** If the manager hangs during shutdown, the hosted test kills only the manager's process group. Workers are spawned in separate groups and intentionally keep running without the manager. A failed run can leave fixed UDP ports occupied until worker self-cleanup. Track the test's owned worker PIDs or use the release runner's lease-scoped cleanup and port check. - Verify the macOS arm64 and Windows x86-64 exports, native SDK redistribution notices and signing, then run the complete acceptance scenario from separate networks. Reproduce the pre-migration interactive LAN gameplay baseline for comparison.
- Run three five-human rooms on the target VM and verify brief recoverable jitter, rendered positions and HP/door sync on a five-player LAN with 60 enemies, and a full-duration five-night game.
